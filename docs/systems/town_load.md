# 마을 처음 열기 재기 (LOAD-1 · 11-13)

> **언제 읽나**: "마을이 늦게 열려요"를 다룰 때 · 모듈 늦게 받기·묶기·줄이기를 제안하기 전에.
> 재기만 한 문서다(게임 코드 `v2/`는 그대로). 숫자는 맥의 머리 없는 크롬으로 한 **흉내**이고 진짜 크롬북이 아니다(§7에 믿을 것·못 믿을 것).
> 재는 법: `zsh tools/ops/b2.sh node tools/harness/town_load.cjs ourtown 8831 --h2` (14분쯤 · 끝 줄 `LOAD DONE`)

## 0. 판정

**가장 큰 몫은 짓기다** — 캐시가 있는 방문(두 번째부터)은 어느 조건에서나 짓기가 55~89%(맥 그대로 3.4초 · CPU 4배 흉내 13~14초). **받기는 처음 방문에서만 크다**(4Mbps 7초 · 1.5Mbps 19~20초 → 두 번째부터 0.4~1.3초). 컴파일은 어디서도 1초 안. → **모듈 늦게 받기는 안 하는 것이 낫다**: 후보 여덟을 다 미뤄도 처음 방문에서만 0.5초(4Mbps)·1.2초(1.5Mbps) = 걸을 수 있을 때까지의 2~5%이고(그 가운데 첫 15분에 실제로 안 쓰이는 다섯만 치면 0.25초), 두 번째 방문과 짓기에는 0, 대신 모듈마다 동기 호출 16~76곳을 고치는 수술이 든다. **다음 걸음 하나 = 진짜 크롬북 한 대의 현장 기록 두 숫자(`t.net` · `bms`)를 받아 §2 표의 어느 줄인지 가리기**(§9).

검토서(`town_review_1110.md` §3-5)의 추정 '처음 열기가 길 것'은 **반만 맞다**: 길기는 하지만(느린 CPU 흉내로 캐시가 있어도 15~16초) 그 까닭이 '모듈 52개를 받느라'가 아니라 '그 기기가 마을을 짓느라'이고, 받기가 긴 것은 캐시가 빈 날뿐이다. (모듈 수도 52가 아니라 직접 93 · 전체 109.)

**서버 = 배포와 같은 전송 꼴**(하네스 안 · node http2 + zlib). 11-13에 배포본 머리말을 확인해 맞췄다: GitHub Pages는 HTTP/2 · `content-encoding: gzip`(br을 받는다고 해도 gzip) · `cache-control: max-age=600` · 약한 ETag. 배포본 `town.js`는 800,364바이트이고 하네스의 gzip 6단계는 782.5KB(0.1% 차). `python3 -m http.server`는 압축을 안 해서 3.6MB가 9MB로 보이므로 이 재기에는 못 쓴다.
- `--h2` = 그 자리에서 만든 인증서로 HTTP/2(본 표). 없으면 HTTP/1.1(연결 여섯) — 차는 첫 화면 0.2초쯤.
- 서버는 `max-age=0`으로 준다 = '10분 지남' 꼴(파일마다 304). **10분 안에 다시 열면** 진짜 Pages에서는 다시 확인도 안 하므로 ② 줄보다도 빠르다.

**잰 신호**(쪽 안 · 주소를 누른 때부터): 첫 그림(로딩 막) → main.js 시작 → 학교 끝 → 마을 모듈 다 받음 → **첫 화면**(제목·저장 칸 = `SM_T_RDY`) → 다 지음 → **걸을 수 있음**(짓는 덮개가 걷힘). 하네스는 첫 화면이 뜨자마자 단추를 누른다 — 마을은 제목 뒤에서 계속 지어지므로 '걸음'은 **가장 빨리 누른 아이**의 값이다(칸을 10초 고르는 아이는 그만큼 덜 기다림).

## 8. 재는 법

```
zsh tools/ops/b2.sh node tools/harness/town_load.cjs ourtown 8831 --h2
```
- 옵션: `--reps=3` · `--nets=free,4m,1m5` · `--cpus=1,4` · `--visits=3` · `--out=폴더`(결과 JSON `town_load_h2.json`) · `--soon`(저장 손 표시를 묵히지 않음) · `--trace`(한 조건을 트레이스로 — 이름별 컴파일 ms 합)
- 서버는 하네스가 그 포트에 스스로 열고 닫는다(따로 `http.server`를 띄우지 않음). `openssl`이 없는 곳은 `--h2`를 빼고.
- 그리기를 켜고 재는 무거운 시험이라 `b2.sh`가 한 자리만 준다. CPU 4× 숫자는 부하가 낮을 때(1분 부하 4 아래)에.

## 9. 다음 걸음 하나 — 진짜 크롬북의 두 숫자

교사가 수업 크롬북 한 대에서 마을을 열고 선생님 칸 「화면 기록 복사」(PERF-G · `perf.md`)를 붙여 주면, 그 기록의 두 칸으로 가린다.

| 칸 | 값 | 뜻 |
|---|---|---|
| `t.net`(마을 모듈 받기 끝 · 초) | 3 아래 | 캐시가 살아 있음 — 받기는 문제가 아님 |
| | 7 넘음 | '처음' 줄 — 캐시가 비었거나 지워짐 → 코드보다 운영(수업 전에 그 크롬북으로 한 번 열어 두기 · Ctrl+Shift+R 대신 Ctrl+R)이 먼저 · 그래도 모자라면 §6의 주석 빼기 |
| `bms`(마을 짓기 ms) | 4,000 안팎 | 1× 줄 — 열기는 5초 안팎이라 '덜 쾌적'의 까닭이 열기가 아님 |
| | 13,000 안팎이나 그 위 | 4× 줄 — 짓기가 범인. 늦게 받기로는 못 줄임 |

숫자가 오기 전에는 열기 쪽 코드를 고치지 않는다.
