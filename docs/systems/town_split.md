# town.js 쪼개기 설계안(SPLIT-1 · 10-17 · 엔진 팀 · 아직 옮기지 않음)

사용자 10-17: "리팩터링은 네가 필요할 때 해도 됨". 지금은 팀 여덟이 town.js를 동시에 고치고 있어서 바로 옮기면 충돌이 크다. 그래서 이 문서대로 **메인이 조용한 날(팀이 적은 날) 한 모듈씩** 옮긴다. 옮기는 날에는 동작을 바꾸지 않는다. 정리, 이름 바꾸기, 고치기도 함께 하지 않는다.

## 1. 지금 모습(0750dbc에서 잼)
- town.js 5,293줄. `export default async function start(map, params)` 하나 안에 위 선언 1,082개(이름 1,203개)가 한 닫힘(closure)을 같이 쓴다.
- 이미 떼어 낸 파일은 23개(town_*.js)다. 자료 표(ITEMS·BUGS…)와 작은 엔진(createStory·createSubway·createFriends…)이고, **`createX(api)` 꼴**이다. 바뀌는 값은 `en: () => LANG === 'en'` 같은 '읽기 함수'로 넘긴다. 새 모듈도 이 꼴을 따른다.
- 팀 패치 충돌이 잦은 줄: `window.SM_TOWN = {` 한 줄, `stop() {` 한 줄, 매 프레임 tick 줄. 거의 모든 팀이 이 셋에 무언가를 끼운다.
- 잰 도구(스크래치에 있음): `split_scan.cjs`(문자열·주석을 뺀 토큰으로 위 선언과 서로 부르는 이름), `split_group.py`(구획·이름 규칙으로 모듈 나눔 + `git blame` 날짜), `split_mut.py`(모듈을 건너 쓰는 '다시 대입' 변수). 옮기기 전날 다시 돌려 숫자를 새로 잰다.

  - 함수·상수(`ty`·`cellOf`·`nameOf`·`TY`·`G`·`REG` …)는 `createX(C, TS)`의 `C`로 넘긴다. 모듈 맨 위에서 한 번 구조 분해한다.

- **고쳐 쓸 자리 수**(남의 '다시 대입' 변수를 쓰는 자리 / 남의 함수·상수를 쓰는 자리):

- **두 길 견주기:**
  - **(가)** 기존 꼴('읽기 함수')로 옮길 때마다 그 자리를 고친다. 모듈마다 고칠 곳이 흩어지고, 옮기는 날 확인할 것도 늘어난다.
  - **(나, 권함)** **0단계로 town.js 안에서 먼저 `TS.`를 붙인다.** 1,865곳을 한 번에 하고, 아직 한 파일 안이다. 그래서 그림 지문·상태 교차로 '같음'을 바로 증명한다. 그 뒤 옮기기는 줄을 거의 그대로 옮기면 된다.
- 매 프레임 비용: `TS.x` 읽기는 속성 하나이고, 모듈 경계를 넘는 호출도 같은 함수 호출이다. `C`·`TS`는 시작할 때 한 번 만들고, 매 프레임 새 객체나 클로저를 만들지 않는다(town_lessons E '렉').

## 4. 옮기는 차례(팀 패치 충돌이 가장 적은 차례)
기준은 셋이다. 오늘 고친 줄이 적을수록, 남이 쓰는 이름이 짓기 뒤 바뀌지 않는 것일수록, 덩어리가 클수록(떼면 town.js가 많이 줄어 다음 충돌이 준다) 먼저 옮긴다.

| 차례 | 할 일 | 까닭 |
|---|---|---|
| 0 | `TS` 바꾸기(코드 이동 없음 · town.js 안) | 1,865곳 한꺼번에 · 팀이 가장 적은 날 · 그날 들어온 팀 패치는 `TS.` 붙여 다시 만들게 알림 |
| 1 | **짓기** → town_build.js | 3,152줄 · 오늘 6%로 가장 차가움 · 떼면 town.js 5,293 → 약 2,100줄 |
| 2 | **입력·키** → town_input.js | 작음 · 꼴(createX(C, TS)) 시범 겸 |
| 3 | **탈것** → town_ride.js | 지하철·버스가 오늘 막 들어옴(44%) · 하루 쉬고 |
| 4 | **생활 tick** → town_life.js | 36% · `makeLife` 236줄이 이미 한 함수라 옮기기 쉬움 |
| 5 | **창·대화 UI** → town_ui.js | 50% · UI-2·수첩·메뉴 팀이 끝난 뒤 |
| 6 | **이야기 api** → town_story_api.js | 95%로 가장 뜨거움 · 이야기 팀이 3막까지 끝낸 뒤 마지막 |

- 남는 town.js(core)는 약 600줄이다. 시작·공용 상태·tick 차례·stop·`SM_TOWN`만 남는다.
- **충돌이 잦은 세 줄**(`SM_TOWN`·`stop`·tick)은 0단계 때 **등록부**로 바꾼다. 모듈이 `TS.onStop.push(fn)`·`TS.ticks.push(fn)`·`Object.assign(SM_TOWN, {...})`로 제 것을 붙이게 해서, 팀이 같은 한 줄을 고치지 않게 한다. tick 차례는 지금 순서 그대로 배열에 둔다.
- 한 번에 한 모듈, 하루에 하나. 옮기는 날 그 모듈을 건드리는 팀 패치는 받지 않는다(동결).

## 5. 한 모듈 옮기는 법
1. 줄 내용은 그대로 옮긴다(들여쓰기·주석 그대로). 그래야 git diff가 '줄 이동'으로 보이고, 나중 팀 패치의 문맥이 새 파일에서도 같다.
2. 새 파일:
   ```
   export function createBuild(C, TS) {
     const { map, T3, ... } = C;
     /* 옮긴 줄들 */
     return { build, ty, ... };
   }
   ```
3. town.js 쪽: `const B = createBuild(C, TS); Object.assign(C, B);` 한 줄을 지금 그 구획이 있던 자리에 둔다. 그래야 선언 순서(TDZ)가 그대로다.
4. import에 `?v=1`을 붙인다. 캐시 번호는 메인이 한꺼번에 올린다.
5. 옮긴 뒤 들어온 팀 패치는 `git apply --3way`가 실패할 수 있다. 그때는 hunk 문맥(줄 내용)으로 새 파일에서 같은 자리를 찾아 적용한다(도구는 옮기기 첫날 만든다).

## 7. 하지 않는 것

- 이미 떼어 낸 자료 표(town_game.js·town_bugs.js …)는 그대로 둔다.
