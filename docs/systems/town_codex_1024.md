**3. 남은 예산의 우선순위**

**화산·화석을 다시 후순위로 밀지 않는 편이 좋습니다.** 안정화 뒤 바로 사용자에게 보이는 대표 결과를 만드세요. 체력 완성을 선행 조건으로 두지 마세요.

아래 숫자는 소요량 예측이 아니라 **작업 중단·재판단 상한**입니다.

| 순서 | 사용량 구간 | 끝낼 결과 | 까닭 |
|---|---:|---|---|
| 1 | 49→52% | 저장·119 재개 문제, 이미 합친 기능의 진행 막힘 정리 | 새 기능 때문에 기존 진행을 잃으면 신뢰가 더 크게 떨어짐 |
| 2 | 52→57% | 화산·화석 최소판. 접근·출구·도구 행동·남는 관찰 기록 | 가장 기다린 변화. 탐험·과학·눈에 보이는 결과를 한 번에 전달 |
| 3 | 57→59% | 지도 버스 노선과 축척 가림 | 이미 있는 넓은 마을과 놀이의 접근성이 좋아짐 |
| 4 | 59→62% | 학교 가까운 빈 칸 5~10곳에 기존 규칙 연결 | 첫 30분의 빈 이동을 직접 줄임 |
| 5 | 62→64% | 여유가 있으면 행정복지센터 한 곳의 신고→수리 | 빈 건물의 역할과 사회 배움을 눈으로 보여 줌 |
| 6 | 64→68% | 통합·크롬북·홍보판·첫 30분 검증과 수정 | 사용 가능한 결과로 마무리 |
| 7 | 68→69% | 막판 결함 수정·안정판 복귀·보고 | 70% 경계에서 미완성 통합을 남기지 않기 |

**앞 단계가 상한을 넘으면 5번부터 뺍니다. 검증 몫을 빼서 기능을 추가하지 않습니다.**

화산·화석 최소판에도 다음은 있어야 합니다.

| 반드시 있음 | 다음으로 미룸 |
|---|---|
| 멀리서 보이는 지형, 실제 접근로, 걸어서 나오는 출구 | 용암 동굴·새 시설 |
| 암석 비교 또는 지층의 위아래를 쓰는 관찰 | 여러 코스·상급 도전·체력 잠금 |
| 삽·솔 등 기존 도구로 드러나는 변화 | 대규모 발굴·복잡한 날씨 연쇄 |
| 다음에 봐도 남는 기록·흔적 | 썰물섬·스키 기문·음식 효과 |

**그래서 할 일:** 이번 주 대표 결과를 ‘화산·화석을 실제로 다녀와 관찰 흔적을 남긴다’로 정하세요. 지도·빈 칸 개선을 그 왕복 경험에 붙이세요.

**4. 토큰을 아끼면서 진도를 내는 작업 규칙**

지금 병목은 구현 인원보다 **동시에 건드리는 공통 코드, 오래된 기준판, 합친 뒤 재작업**입니다.

현재 `town.js`는 약 **1.75MB·6,644줄**입니다. 한 줄은 최대 약 **2만 2천 자**입니다. 줄 수보다 한 줄에 여러 책임이 섞인 구조가 검색·검토·충돌 해결 비용을 키웁니다.

| # | 권할 규칙 |
|---|---|
| 1 | **메인 + 구현 팀 하나가 기본.** 파일과 연결 지점이 겹치지 않을 때만 둘. 여섯 팀 동시 진행은 중단 |
| 2 | **맡기는 단위는 아이가 확인할 결과 하나.** 입력 상태·수정 파일·끝 기준·시험을 짧게 지정. ‘탐험 전체’, ‘빈 건물 전체’ 금지 |
| 3 | **30~45분마다 계속할지 재판단.** 결과 없이 조사만 길어지면 범위를 줄임. 기존 설계를 다시 여러 안으로 토론하지 않음 |
| 4 | **town.js와 공통 상태 연결은 한 사람이 소유.** 팀은 독립 모듈과 작은 연결 제안을 제출. 캐시 번호도 메인이 관리 |
| 5 | **기준 커밋을 작업 카드에 기록.** 제출 전에 최신 통합판에 맞추고 관련 시험 수행. 충돌이 나면 작성자가 의미를 확인하고 다시 제출 |
| 6 | **합치기는 한 조각씩.** `git apply -3` 성공을 호환성 증명으로 보지 않음. 시작·중단·잠·저장·재개 처리가 겹쳤는지 확인 |
| 7 | **시험은 순수 규칙 → 해당 기능·상태 교차 → 통합·성능 순서.** 공통 저장·이동·창 처리가 바뀌면 곧바로 관련 넓은 시험. 그림을 끈 시험은 화면·GPU 검증을 대신하지 못함 |
| 8 | **3D 브라우저는 맥 전체에서 하나.** 전역 잠금과 종료 시 정리 보장. 팀은 가벼운 시험, 메인은 실제 화면 시험을 담당 |
| 9 | **메인 세션은 완료 묶음 1~2개마다 정리.** 기준 커밋·완료·실패·다음 한 조각·남은 예산을 한 장으로 넘김. town.js 전체 재독과 긴 대화 누적을 피함 |
| 10 | **20~30분마다 짧게 보고.** ‘지금 끝난 것 / 게임에서 확인할 곳 / 막힌 것 / 실제 사용량’을 전달. 완료 때는 커밋과 검증 결과를 붙임 |

시험 쪽에서 특히 고칠 점이 있습니다.

| 확인한 점 | 필요한 조치 |
|---|---|
| [town_check.cjs:17](tools/harness/town_check.cjs:17)은 오류·측정치를 출력하지만 실패 종료 판정이 없음 | 실행 성공과 검사 통과를 분리. 바깥 실행기가 JSON을 판정한다면 그 조건을 명시 |

`town.js` 전체 분리는 이번 주에 하지 않는 편이 낫습니다. **새 기능부터 독립 파일로 만들고**, 이후 창 상태·이동·저장처럼 경계가 확인된 부분을 하나씩 옮기세요. 긴 줄 전체 포맷 변경과 기능 변경을 동시에 하면 충돌 비용이 커집니다.

홍보판은 요청한 기간의 **루트 `index.html` 변경 커밋이 없었습니다.** 다만 공통 JS가 바뀌면 영향은 생길 수 있으므로, 파일 무변경 검사와 홍보판 실행 확인을 함께 해야 합니다.

**그래서 할 일:** 팀 수를 줄이고, 공통 파일 소유권과 최신 기준판 확인부터 적용하세요. 시험 개수보다 **실패를 제대로 막고 있는지**를 먼저 보세요.
