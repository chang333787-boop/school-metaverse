# 🔑 v4 계정 구조(ACCT-1 · 10-18)

사용자 10-18: "총관리자(나) / 관리자(다른 선생님) / 선생님이 학교·반 설정 — 아이디 만들기(나도 있어야 함) / 애들은 학교 코드 및 개인 핀으로 로그인 · 이 구조 그냥 만들어 · v4만 해당"

v4(마을 입구)에만 적용한다. 학교 놀이(v2)·홍보판은 그대로(로그인 X).

## 1. 역할 넷
| 역할 | 누가 | 할 수 있는 것 |
|---|---|---|
| **총관리자** | 사용자(1명) | 관리자 지정·해제 · 모든 학교 보기 · 학교 만들기·닫기 · 계정 잠금 풀기 |
| **관리자** | 다른 선생님(학교 단위) | 자기 학교의 선생님 계정 만들기 · 반 만들기 · 자기 학교 기록 보기 |
| **선생님** | 담임 | 자기 반 설정(학년·반 이름·학생 수) · 학생 아이디 만들기·핀 다시 정하기 · 반 기록 보기 · 함께하기 방·선생님 칸(TOGETHER-1) |
| **학생** | 아이 | 학교 코드 + 번호 + 개인 핀으로 들어오기 · 자기 진행만 |

- 총관리자도 선생님 계정을 하나 가진다(자기 반 수업용 — "나도 있어야 함").
- 한 사람이 여러 역할: 총관리자 ⊃ 관리자 ⊃ 선생님 권한.

## 2. 로그인
- **어른(총관리자·관리자·선생님):** 아이디 + 비밀번호(8자 이상). 처음 총관리자 계정은 사용자가 직접 한 번 만든다(첫 실행 때만 열리는 '총관리자 만들기').
- **학생:** ① 학교 코드(6자 · 선생님이 칠판에) → ② 반 고르기 → ③ 번호 → ④ 개인 핀(그림 넷 또는 숫자 넷 — 반 설정에서 고름). 지금 v4의 번호 + 그림 비밀번호 화면을 그대로 넓힌다.
- 핀을 잊으면: 선생님이 반 화면에서 그 번호의 핀을 지움 → 아이가 새로 정함(기록은 남음).
- 같은 학생이 두 기기에서 들어오면 나중 것만 남음.

## 3. 자료(이름은 서버에 두지 않음 — 공개 저장소·공개 DB)
- `acct/schools/<학교코드>` = { 이름(선생님이 정한 별칭 · 실제 학교명 X 권장), 관리자 목록 }
- `acct/classes/<학교코드>/<반id>` = { 학년, 반 이름, 학생 수, 핀 방식, 선생님 }
- `acct/students/<학교코드>/<반id>/<번호>` = { 핀 해시(학교마다 다른 소금 + SHA-256), 잠금 }
- `acct/staff/<아이디>` = { 역할, 학교코드, 비밀번호 해시 }
- 학생 진행·기록 = `play/<학교코드>/<반id>/<번호>` — 하루 한 번 묶어 올림(REC-0 꼴 그대로) · 새 스트림 X
- **이름:** 학생 이름은 서버에 두지 않는다. 선생님 기기 안에서만 '번호 ↔ 이름' 표(선생님이 입력 · 그 기기에만)를 두고 반 화면에 이름을 붙여 보여 준다.

## 4. 화면
- **v4 첫 화면:** [학생으로 들어가기] [선생님으로 들어가기]
- **선생님 화면:** 내 반(학생 번호 표 · 핀 지우기 · 오늘 들어온 아이 · 반 기록 — 학급 기록 화면 꼴) · 반 설정 · 함께하기 방 열기
- **관리자 화면:** 학교 선생님 목록·만들기 · 반 목록
- **총관리자 화면:** 학교 목록·관리자 지정
- 모두 UI-2 창 결(종이·잉크 테두리 · 슬롭 X).

## 5. 보안·한계(솔직히)
- 지금 Firebase DB는 공개 읽기·쓰기(교사가 알고 정한 것). 이 구조를 제대로 지키려면 **DB 규칙을 바꿔 배포**해야 한다(학생 칸은 그 학생·그 반 선생님만 쓰기 · 계정 칸은 역할로 막기). 규칙을 바꾸기 전까지는 '잠금장치가 있는 척'일 뿐 — 마음먹은 사람은 DB를 직접 읽고 쓸 수 있음.
- 더 단단하게 하려면 어른 로그인은 Firebase 인증(이메일·구글)으로 — 이건 선생님 결정.
- 핀은 해시로만 저장 · 5번 틀리면 1분 잠금.

## 6. 짓는 차례(사용량 초기화 뒤)
1. 자료 꼴 + 해시 + 학생 로그인(학교 코드 → 반 → 번호 → 핀) · 지금 v4 번호 로그인을 바꿈(이 기기 저장은 서버 진행으로 옮겨 줌)
2. 선생님 화면(반 설정 · 학생 아이디 만들기 · 핀 지우기 · 반 기록)
3. 관리자·총관리자 화면
4. DB 규칙 초안(배포는 선생님 확인 뒤) · 함께하기(TOGETHER-1)와 잇기
- 시험: 학교 둘·반 둘·학생 넷 시험 계정은 `zz`로 만들고 끝나면 지움.

## 선생님 결정이 필요한 것
1. DB 규칙 바꿔 배포할지(위 §5).
2. 어른 로그인을 아이디·비밀번호로 할지, 구글 로그인으로 할지.
3. 학생 핀: 그림 넷 / 숫자 넷.

## 결정(사용자 10-18 '추천으로')
1. **DB 규칙 배포 = 함.** 새 칸(`acct/` · `play/`)에만 잠금(학생 칸 = 그 학생·그 반 선생님만 쓰기 · 계정 칸 = 역할로) · 이미 열어 둔 다른 칸(우리반RPG 등)은 그대로.
2. **어른 로그인 = 구글 로그인(Firebase 인증).** 총관리자 = 사용자 구글 계정 하나(처음 한 번 지정) · 관리자·선생님도 구글 계정으로 들어오고 역할은 `acct/staff/<uid>`에.
3. **학생 핀 = 그림 넷**(8개 가운데 · 지금 v4 화면 그대로).
- 구글 로그인을 쓰려면 Firebase 콘솔에서 'Google 로그인 사용'을 켜야 함 — 만들 때 콘솔에서 켜는 곳을 알려 드리고, 켜졌는지 확인한 뒤 잇는다.
