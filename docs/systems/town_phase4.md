# 단계 4 설계(PHASE4) — 엔진 여덟

> 차례표 F 22~29줄. 안 셋(시스템 설계자 · 과학·사회 교사 · 크롬북 수비수)과 반박 셋을 합친 최종안이에요.

## 한눈에 — 서로 맞물리는 모습

날씨 전선이 뿌리예요. 비 띠가 마을을 지나가면 칸 상태판(`SIM`)의 **비·젖음**이 바뀌어요. 나머지 엔진은 서로 함수를 부르지 않고 이 판만 읽고 써요.

- 전선(22) → 젖음 → **물 흐름(26)**: 호수(사8)에 물이 모이고, 강을 따라 라12 징검다리까지 와서 수위가 올라요. 수위는 다시 나뭇잎 배와 공(27)의 떠내려가는 빠르기가 돼요.
- 전선 → 지역별 사흘 비 → **장터 공급(23)**: 바구니에 물건이 덜 쌓이고 값이 바뀌어요.
- 전선 → 내 둘레 비 → **이웃 일과(25)**: 이웃이 처마로 가고 우산을 펴요. 장날 붐빔은 장터 값의 수요가 돼요.
- 젖음·물 맑기·꽃 → **먹이 연쇄(24)**: 곤충 → 개구리 → 왜가리·백로로 이어져요. 흙탕물이 되면 수달이 나오지 않아요.
- 전선이 다가오는 때 → **소금(28)**: 진한 소금물을 창고에 들이는 판단. 맑고 바람 부는 칸이면 소금이 많이 나요. 소금은 다시 장터(23)로 가요.
- 젖음·계절·바람 → **그림 결(29)**: 논의 색과 물결이 바뀌어 보여요.

## 공용 칸 상태 — `v2/games/town_sim.js`(새 모듈 · town.js에는 연결 몇 줄만)

- **칸 번호** `ci(x,z)`: 0~139 정수를 돌려줘요. `cellOf`가 쓰는 `eIdx(MXof(x),XE)` 경계 배열을 그대로 쓰고, 새 문자열은 만들지 않아요. **1칸은 약 125m예요**(판 25cm × 5m/cm · 판 전체 1750×1250m). 50m라고 적었던 안을 고쳤어요.
- **상태판** `SIM = Float32Array(140 × 10)` 한 개를 모듈 위에서 한 번만 만들어요. 칸마다 열 칸이에요: 0 비 · 1 젖음 · 2 흐르는 물 · 3 꽃 · 4 곤충 · 5 개구리 · 6 물 맑기 · 7 물가 쓰레기 · 8 붐빔 · 9 예비.
- **도는 때**
  - 1초를 125ms 자리 여덟 개로 나눠 엔진마다 자기 자리에서만 돌아요. **0번 자리는 비워 둬요.** 이미 `wxq === 0` 프레임에 `umbSec`·`CHEM.sec`·`RD.sec`가 몰려 있기 때문이에요.
  - 하루에 한 번 하는 셈(먹이 연쇄·장터 공급)은 `emit('day')`에 걸어요. 같은 일이 몰리지 않게 1.5초 뒤에 돌려요(OPT-11 꼴).
  - 매 프레임 하는 일은 uniform 몇 개와 걷는 일꾼 보간뿐이에요.
- **땅에 보이는 판**: `SIMTEX`는 지도 전체를 덮는 28×20 텍셀 데이터 텍스처예요. 칸 값을 1초에 한 번 다시 써 넣고, LinearFilter로 경계를 흐리게 해요. 칸 경계가 고르지 않아도 되고, 125m 바둑판 무늬도 생기지 않아요. 젖은 땅과 ART-3 셰이더가 이 판을 읽어요.
- **저장**(GAME 2초 flush만 · 날 바뀔 때만 씀)

  ```
  S.sim = { v:1, d, eco:{ci:[꽃,곤충,개구리,맑기,쓰레기]}(바뀐 칸만), r3:{지역:[오늘,어제,그제 비 양]}, salt:{lv:{}} }
  ```

  전선·수위·일과는 `hashS(id)+날` 씨앗과 시계로 다시 셀 수 있어서 저장하지 않아요. 합계는 1.6KB 아래예요.
- **끄는 규칙**
  - `wxAuto()`가 false(날씨 단추로 고정)이거나 함께하기에서 선생님이 날씨를 고정하면 전선이 꺼지고 마을 전체가 한 날씨가 돼요. 지금과 같아요.
  - 선생님 칸에 **'전선 비'** 단추를 더해요. 예보대로 전선만 켜는 단추라서 수업 시연에 써요.
  - `SM_PROMO`에서는 여덟 엔진이 모두 꺼져요.
  - `?simoff=front,flow,mk,life,eco,ball,salt,art`로 엔진을 하나씩 끌 수 있어요.
- **재기 손잡이**: `SM_TOWN.sim = { cell(nm), front(), at(h), eng() }`. `eng()`는 엔진마다 1초 칸 ms 평균·최대, 그리기 더함, 저장 바이트를 돌려줘요(`wild`의 secMs 꼴). 화면에는 절대 나오지 않아요.

## 엔진마다 한 칸

### 22 날씨 전선
- **규칙(실제)**
  - 비 오는 날(`fcW(0)==='rain'`)에는 비 띠 하나가 바람 오는 쪽에서 들어와요. 우리나라는 대체로 서쪽에서 와요. 비 오는 날만 `windOf`를 서풍 쪽으로 기울여서, 땅 바람과 띠의 방향이 어긋나지 않게 해요.
  - 빠르기는 게임 1시간(실제 42초)에 약 1열이고, 띠 폭은 2~3열이에요. 그래서 한 곳에는 게임 2~3시간(실제 1.5~2분) 동안 비가 오고, 띠가 마을을 다 지나는 데는 하루 대부분이 걸려요. '비 오는 날인데 내 칸은 거의 맑음'이 생기지 않아요.
  - 산 칸(`regionOfCell`이 산을 돌려주는 곳, `c<=5 && r<=3`)은 바람받이라 한 열 먼저 오고 1.5배 길게 와요.
  - 비 오는 날 셋 중 하나 꼴로 **비그늘 날**이 있어요. 띠가 산에서 멈추는 날이라, 예보를 보고 판단할 거리가 남아요.
  - 흐린 날 오후에는 **산 소나기**가 생겨요. 산 칸 하나에 게임 1시간쯤이에요. 1일째에도 산 위에만 생기게 해서, 처음 들어온 날 내 동네는 맑다는 규칙을 지키면서 멀리서 비를 볼 수 있어요.
  - **먼저 확인할 것**: 열 숫자가 커질수록 정말 동쪽인지 `MXof`·`GRD.order`로 재요. 틀리면 '서쪽에서 온다'가 거짓말이 돼요.
- **비 세기는 연속 값이에요.** 칸이 아니라 내 자리에서 띠 앞줄까지의 거리로 정하는 `rainAt(x,z,분)` 식 하나로 구해요. 140칸을 돌지 않아요. 가장자리는 부드럽게 줄어들어요.
- **조용한 날씨 길**: 칸을 드나들 때는 `setWeather`를 부르지 않아요. `setWeather`는 부를 때마다 메시를 다시 짓고, 토스트를 띄우고, 날씨 창을 닫고, 무지개를 부르기 때문이에요. 대신 이렇게 해요.
  - 새 함수 `wxHere(v)`가 WX9만 바꾸고 빗방울은 drawRange로 세기만 바꿔요. 비·눈 버퍼는 `makeWeather`에서 처음 한 번만 만들어 둬요. 바꾼 값이 5초 이어질 때만 실제로 바꿔요.
  - 토스트는 하루에 처음 젖을 때 한 번만 떠요.
  - `setWeather`는 손 고정과 날 바뀜에만 남겨요.
- **WX9를 쓰는 곳은 하나씩 나눠요.** 표를 만들어 '하루 날씨' `wxDay()` 쪽과 '내 칸 날씨' WX9 쪽으로 갈라요.
  - 하루 날씨: 텃밭 비 물주기 `rainW`, 이야기 단계 `type:'rain'`·`d.wx`, 일 놀이 조건
  - 내 칸 날씨: 우산, 기온, 반딧불이, `LOOKX` 하늘 톤
- **보이는 것**
  - 띠 하나 = 낮은 먹구름과 얇은 세로 커튼 두 장(앞·뒤)을 인스턴스 메시 하나로 그려요. 그리기 +1이고, 비가 없으면 0이에요.
  - 내가 띠 안에 있으면 커튼을 숨겨요. 화면을 덮는 덧칠을 막으려는 거예요. `depthWrite:false`로 두고, 안개 거리 안에서만 보여요.
  - 구름 판이 움직이는 것 자체가 '서쪽에서 온다'는 증거예요.
  - 무지개는 하루 한 번만 떠요. 띠가 내 자리를 막 지나갔을 때, 해 높이가 42°보다 낮을 때(아침·늦은 오후)만이고, 자리는 `SUN`(town_look.js)의 반대편이에요. 지금처럼 '보는 방향 300m'에 띄우지 않아요.
- **기상캐스터 = 창 없이 손 보태기**
  - 예보(`openWx` 한 줄)는 칸 주소나 시각 없이 방향만 말해요. 예: "오후에 서쪽 산에서부터 비가 와요."
  - 언제 내 동네에 오는지는 아이가 높은 곳에서 구름 판을 보고 정해요. 증거 물체는 바람개비·풍향 깃발 몇 개(인스턴스 하나 · 높은 곳과 정문)예요.
  - 하늘이 어두워지면 이웃이 스스로 서둘러요. 아이가 할 일은 **비가 오기 전에 몸으로 옮기기**예요: 염전의 진한 소금물을 창고에 들이기(28), 노점 바구니에 덮개 끌어 덮기(23).
  - 비가 실제로 오면 결과가 세상에 남아요. 들여놓은 소금은 남고, 덮은 바구니는 마른 색이에요.
  - 맞힌 수나 별은 없어요. 보상은 `GAME.add(…,'wx:warn')`으로 rwCheck 문 하나만 지나요.
  - 빨래는 `homeLife`의 dbx 병합이라 하나씩 걷을 수 없어서 이번에는 빼요.
- **우와 셋**
  1. 언덕에서 보면 산에만 비 커튼이 서 있고 내 동네는 해가 나요.
  2. 커튼 가장자리를 걸어 나오면 빗소리가 줄고, 젖은 땅에 경계선이 보여요.
  3. 미리 들여놓은 소금과 덮은 바구니만 비 뒤에도 말라 있어요.
- **배움**: 날씨는 옮겨 다녀요. 산에 비가 많은 까닭도 다뤄요. 다만 2022 개정에서 몇 학년 단원인지 확인하기 전에는 화면에 단원명을 쓰지 않아요.
- **비용**: 1초 칸 0.15ms · 그리기 +1 · 매 프레임 uniform 하나.
- **시험**: 씨앗을 고정한 10일 동안 아래를 봐요.
  - 비 오는 날의 95%에서 산이 먼저 젖어요.
  - WX9가 1분에 세 번 넘게 바뀌는 일이 0이에요.
  - 날씨가 바뀌어 창이 닫히는 일이 0이에요(`town_state.cjs`에 '전선 × 창' 줄을 더함).
  - 30분 수업에서 비 칸을 하나라도 보는 비율이 80% 이상이에요.

### 23 장터 값
- **규칙**
  - `priceAt`에 공급 지수 하나를 곱해요. 공급 지수는 그 지역의 **사흘 쌓인 비**(`r3`)와 제철로 정해요. 하루 비로 값이 오르는 잘못된 인과를 피하려는 거예요. 실제로 채소 값은 비가 이어질 때 올라요.
  - 수요 지수는 장날 판정(priceAt의 ×1.2와 같은 값)과 장터 칸 일꾼 수로 정해요. 길 사람 `makeLife`는 내 둘레에 모이는 사람이라 쓰지 않아요. 쓰면 되먹임이 생겨요.
  - 공급 × 수요는 **0.85~1.15로 가둬요**. 먼 곳 ×1.3과 `demK`(많이 팔면 내려감)는 그대로 그 뒤에 곱해요. 새 3% 규칙은 두 번 깎이는 셈이라 버렸어요.
- **보이는 것**
  - 값보다 **물량**이 먼저 보여요. 공급이 적으면 노점 바구니 소품 개수를 줄여요. 있는 소품의 count만 바꾸니 그리기는 0이에요.
  - 장터마다 칠판 하나(`textSign` 캐시)에 오늘 값 숫자만 써요. 아침에만 다시 그리고, 화살표·%는 없어요.
  - 까닭은 두 번째로 말을 걸 때 상인이 말해요. 예: "며칠 비가 와서 밭에 못 들어갔대요."
- **우와 셋**
  1. 사흘 비 다음 날 들 장터 배추 바구니가 비어 있고 칠판 값이 달라요.
  2. 한 장터에 감자를 몰아 팔면 그 장터만 값이 낮아지고, 다른 장터는 그대로예요(`demK`가 보이게).
  3. 맑고 바람 부는 날 소금이 많이 나면 다음 날 바다 장터 소금 바구니가 가득해요.
- **배움**: 수요와 공급 · 날씨와 생산 · 지역 사이 교류(사회). 셈 문제는 없고 읽고 견주기만 해요.
- **비용**: 매 프레임 0 · 1초 칸 0 · 칠판 = 장터 수만큼.
- **시험**: `econ_sim`이 저장소에 없어서 먼저 `tools/harness/town_econ.cjs`로 옮겨요. 사흘 비 다음 날 시나리오에서 하루 벌이가 ±15% 안이어야 하고, 되사서 되팔면 늘 손해여야 해요. `town_cap.cjs`도 통과해야 해요.

### 24 먹이와 서식 연쇄
- **규칙(실제 먹이 관계만 · 원인과 결과 사이는 게임 하루 이하)**
  - 내가 물 준 꽃이나 심은 꽃이 있는 칸은 **그날 몇 분 안에** 배추흰나비·꿀벌 무게가 올라요(BUGSP 고르기). 다음 날이면 더 많아요.
  - 곤충이 많고 물이 맑은 논두렁(`paddyEdge`)에는 참개구리가 와요. 비 온 밤에는 더 나와요.
  - 개구리가 많은 칸에는 다음 아침 백로(`paddyIn`)와 왜가리(`river`)가 와요. 왜가리 먹이 글은 이미 '개구리'예요.
  - 수달은 `clean:1`을 처음으로 읽어요. 물이 맑고 흙탕물이 아닌 날 밤에만 나와요(26과 이어짐).
  - **박새는 넣지 않아요.** 새 종이라 모형·도감·소리가 새로 들어가요. 그리고 '박새가 나비를 쫓는다'는 사실과도 어긋나요.
- **손이 들어가는 곳**: 물가 쓰레기는 날마다 사라지지 않고 천천히 쌓여요(`SIM` 7 · 저장 `eco`). 지금 빗자루 쓰레기 `cellPiles`는 보도에만 생기고 날마다 지워져서 따로 둬요. 아이는 물가에서 손으로 주워요. 그러면 물 맑기가 오르고, 결과는 다음 날 세상에서 보여요. 벌은 없어요.
- **잇는 곳**: `bugInit` 자리 고르기와 `town_wild.js` `avail(w)`에 `SIM` 칸 무게를 곱해요(`A.allow(id,x,z)`). 이미 1초 칸·20m 판정 구조라 비용은 그대로예요. 도감 일지에는 찾은 것만 한 줄씩 남아요("물가를 치운 뒤 왔어요").
- **우와 셋**
  1. 물 준 꽃밭에 그날 저녁 나비가 날아요.
  2. 물가를 치운 다음 날 비 온 밤 논두렁에서 개구리가 울고, 아침엔 백로가 서 있어요.
  3. 큰비로 흙탕물이 된 밤에는 수달이 안 보여요.

## 저절로 생기는 우와 셋(엔진끼리)

미리 써 둔 결과가 아니라 칸 값에서 생기는 연쇄예요.

1. **산 소나기 한 줄기의 연쇄**: 산에 커튼이 섬 → 내 동네에 오자 이웃이 처마로 감 → 큰비였다면 다음 날 아침 징검다리가 잠기고 길 안내가 다리로 바뀜 → 사흘째 들 장터 배추 바구니가 빔.
2. **미리 본 아이만 남는 소금**: 높은 곳에서 구름이 오는 것을 보고 소금물을 창고에 들임 → 소나기 뒤에도 소금을 만듦 → 다음 날 바다 장터에서 내 소금이 제값을 받음.
3. **물가 손질의 사흘**: 물가 쓰레기를 주움 → 비 온 밤 개구리가 울음 → 아침 백로가 옴. 그런데 큰비로 흙탕물이 된 날 밤엔 수달이 오지 않음.

재는 규칙: 같은 날 씨앗이면 같고, 씨앗을 바꾸면 장면 칸과 시각이 달라야 해요. 그래야 연출 트리거로 하드코딩한 게 아니라는 증거가 돼요.

## 재는 기준
- **성능**(CPU 4× · 1366×768)
  - 렉 순회 p95 < 33ms, 33ms 넘는 프레임 ≤1.5%
  - 1초 칸 합 ≤0.75ms, 한 자리에 ≤0.3ms
  - 그리기: 평소 +4 안, 최악 +7 안(공 놀이 중 + 잠긴 날 + 장터 칠판 수)
  - 30분 힙 증가 0 · 새 Light 0 · 매 프레임 새 객체 0
  - 커튼 앞과 커튼 안에 선 장면의 p95를 따로 재요(덧칠 비용)
- **연쇄**: 30분 한 판에서 엔진이 엔진을 건드린 연쇄를 내가 본 횟수 ≥3(봇 기록 쌍).
- **되풀이**: 다섯째 날이 첫날과 달라요(씨앗).
- **경제**: 하루 벌이 ±15% · 보상은 rwCheck 문 하나.
- **지키는 선**: 판타지 0 · 새 사람 0(물가 안내 이웃도 옮긴 일꾼) · 새 아이콘·%·화살표 0 · 순위·별·맞힌 수 0 · 타이밍 막대 0 · 창으로 끝나는 퀘스트 0 · 셈 0 · 실명 0 · 이모지는 유니코드 12 이전.
